DSH `0.2.1-alpha.4` 不需要功能改动；本版把它列为已验证，并把加载范围挪到 alpha.4 真正校验的那个字段。

兼容最新 DSH `0.2.1-alpha.4`；已验证清单仍保留 `0.2.1-alpha.3`、`0.2.0-rc.2`、`0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1` 与 `0.1.7-alpha.2`。`0.1.8` 及更早版本已发布，本版发布后 npm `latest` 指向 `0.1.9`。

<h3 id="cn-v0.1.9">⚠️ 调整</h3>

- **没有功能代码改动。** 门禁在 DSH 的宽松规则与 node-semver 默认规则下都接纳原有范围，插件行不会被跳过，色块、选择器与 marks 路由一切照旧。
- **范围挪了位置，字符串没变。** alpha.4 起，顶层 `engines.dsh` 一旦存在就单独决定门禁（此时忽略 peerDependencies），市场也读同一字段；原来的 `dsh.engines.dsh` 无人读取。`0.2.1-alpha.3` 及更早的 DSH 不读该字段，仍由 peer 范围决定，行为不变。
- **升级后可见变化只有一处。** `0.2.1-alpha.4` 被明确列为已验证，且本插件对 DSH 版本的要求从此真正被启动门禁与插件市场读取，而不再只是一句说明。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@latest
```

---

DSH `0.2.1-alpha.4` needs no functional code change; this release records it as verified and moves the load range to the field alpha.4 actually enforces.

Verified against the current DSH `0.2.1-alpha.4`; the list also keeps `0.2.1-alpha.3`, `0.2.0-rc.2`, `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1` and `0.1.7-alpha.2`. `0.1.8` and earlier are published; after this release npm `latest` points at `0.1.9`.

<h3 id="en-v0.1.9">⚠️ Changed</h3>

- **No functional code changed.** The boot gate accepts the existing range under both DSH's permissive rule and node-semver's default rule, so the plugin row is not skipped: chips, picker and the marks route behave exactly as before.
- **The range moved, the string did not.** From alpha.4, a top-level `engines.dsh` decides the gate alone when present (peer dependencies are then ignored), and the marketplace reads the same field; the previous `dsh.engines.dsh` is read by nothing. DSH releases up to `0.2.1-alpha.3` do not read the field at all and still gate on the peers, so nothing changes there.
- **There is one visible upgrade effect.** `0.2.1-alpha.4` is explicitly listed as verified, and this plugin's DSH requirement is now actually enforced by the boot gate and the plugin marketplace instead of being a note in the documentation.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@latest
```
