| 插件版本 | 最新核查的 DSH | npm 渠道 |

| `0.1.20`（本版） | `0.2.3-alpha.2` | `latest`（发布后） |
| `0.1.19` | `0.2.2-rc.5` | 已发布 |

### 兼容性与改动

- **修复真实故障**：DSH `0.2.3` 把路由鉴权从 `connection.requestRejection(request)` 挪进了路由声明（`webServer.register({ auth })`，默认 `required`），平台在 handler 之前完成 Host/Origin 校验与认证，并把通过认证的 Peer 作为第三个参数传入；旧方法已被移除。上一版每次都无条件调用它，在 `0.2.3` 上抛错后被「鉴权不可用也不能变成敞开的大门」的 catch 变成 `403`，于是所有已认证请求全被拒绝——侧栏色块消失、选择器读不到也存不了颜色，而插件看上去一切正常。未认证探测仍由平台返回 `401`，所以路由看起来是活的。
- 修复方式：两条路由显式声明 `auth: 'required'`；只在仍提供 `requestRejection` 的版本上按请求调用旧鉴权；没有该方法时，拒绝任何未带 Peer 的请求。两种形态都有测试覆盖，同一份构建同时服务 `0.1.7-alpha.2` 到 `0.2.3-alpha.2`。
- 新增 DSH `0.2.3-alpha.2` 兼容记录，保留此前 17 个已核查版本；同步双语 README、CHANGELOG 与 Release 版本号。
- **Node.js 要求**：自 DSH `0.2.3-alpha.1` 起必须使用 Node.js `24.22.3+`（24.x 线）或 `26.13.1+`（首批内置带 2026 年 11 月安全修复的 `undici`）。更早的 DSH 仍可跑在 Node 20 上，因此本包 `engines.node` 保持 `>=20`，该要求以文档说明。
- 加载范围新增 `>=0.2.3-alpha.2 <0.3.0` 分支（`engines.dsh` 与两个 peer 同步），因此范围本身有变化；存储格式、路由路径与数据格式不变，从 `0.1.19` 升级无需迁移。
- 2026-11-23 npm 渠道：DSH `alpha` → `0.2.3-alpha.2`，`latest` 与 `next` 仍为 `0.2.2-rc.5`。

### 验证与限制

- 逐包对比 `0.2.2-rc.5` → `0.2.3-alpha.2`。客户端契约未变：两个槽位仍有声明（`conversation.session.header.utilities`、`shell.overlay`），会话行仍是 `data-row-key="session:<id>"` + `role="treeitem"` + `aria-selected`，列表仍由 `.listArea`（`overflow: hidden auto`）承载滚动，抽屉属性仍含 `data-sidebar-collapsed` / `data-sidebar-drawer` / `data-sidebar-instant`，手写 `__ModuleLoader__.load({id, factory})` 契约与 locale `register`/`bind` 未变，`react-dom` 仍为外壳静态模块。
- 外壳 `dist` 整体重建（资源哈希全变），但 macOS 拖动规则逐条相同，仍包含 `[data-window-drag-exclude]`，`0.1.17` 的面板声明继续有效。
- Host 侧：`webServer.register` 仍返回 disposer，exact 路由形状相同，新增 `auth` 字段；`connection` 的 `requestRejection` 已移除、改由平台鉴权。
- 43 项单元测试全部通过（含新增 3 项：平台鉴权有 Peer 200 / 无 Peer 401；connection 鉴权拒绝或抛错 403、放行 200）。
- **未完成真实 GUI、移动端或跨设备视觉验收**，修复也未在真实 `0.2.3` profile 上实测（需安装并重启）。没有写入真实标记、没有启动临时服务、没有重启 DSH、没有修改其他插件与本机 profile。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.20
```

发布不会自动更新你的 profile。安装后请在方便时自行重启 DSH 并刷新页面；颜色数据无需迁移。**若你正在 0.2.3 线**，升级前颜色标记会读不到、也存不了，升级并重启后恢复。

### Compatibility and changes

- **Fixes a real break.** DSH `0.2.3` moved route authentication from `connection.requestRejection(request)` into the route declaration (`webServer.register({ auth })`, default `required`), the platform applies the Host/Origin fence and authentication before the handler, and hands the admitted Peer to the handler as the third argument; the old method was removed. The previous release called it unconditionally, so on `0.2.3` the call threw, the "a fence that cannot answer must not become an open door" catch answered `403`, and every *authenticated* request was refused: sidebar chips disappeared and the picker could neither read nor save a colour, while the plugin still looked healthy. Unauthenticated probes still returned `401` from the platform, which is why the route looked alive.
- The fix declares `auth: 'required'` on both routes, keeps calling the per-request fence only on a release that still exposes it, and otherwise refuses any request that arrives without a Peer. Both shapes are covered by tests, so one build serves `0.1.7-alpha.2` through `0.2.3-alpha.2`.
- Add DSH `0.2.3-alpha.2` compatibility, retaining the 17 previously assessed versions; synchronise both READMEs, CHANGELOG and Release versions.
- **Node.js requirement:** from DSH `0.2.3-alpha.1`, Node.js `24.22.3+` (24.x line) or `26.13.1+` is required — the first releases whose bundled `undici` carries the November 2026 security fixes. Older DSH still runs on Node 20, so the package's own `engines.node` stays `>=20` and the requirement is documented instead.
- The load range gains a `>=0.2.3-alpha.2 <0.3.0` alternative (`engines.dsh` and both peers), so the range itself does change; storage format, route paths and data format are unchanged, and no migration from `0.1.19` is needed.
- Registry channels on 2026-11-23: DSH `alpha` → `0.2.3-alpha.2`, while `latest` and `next` remain `0.2.2-rc.5`.

### Verification and limits

- Compared every consumed package across `0.2.2-rc.5` → `0.2.3-alpha.2`. Client contracts are unchanged: both slots are still declared (`conversation.session.header.utilities`, `shell.overlay`), Session rows still carry `data-row-key="session:<id>"` with `role="treeitem"` and `aria-selected`, the list still scrolls inside `.listArea` (`overflow: hidden auto`), the drawer attributes still include `data-sidebar-collapsed` / `data-sidebar-drawer` / `data-sidebar-instant`, the hand-authored `__ModuleLoader__.load({id, factory})` contract and locale `register`/`bind` are untouched, and `react-dom` is still a shell static module.
- The shell `dist` was rebuilt wholesale (every asset hash changed), but the macOS drag rules are identical and still include `[data-window-drag-exclude]`, so the `0.1.17` panel declaration keeps working.
- Host side: `webServer.register` still returns a disposer and the exact-route shape is the same apart from the new `auth` field; `connection.requestRejection` is gone and the platform now fences routes.
- All 43 unit tests pass, including three new ones: platform fencing serves 200 with a Peer and refuses 401 without one; the connection fence yields 403 when it refuses or throws and 200 when it admits.
- **No real GUI, mobile or cross-device visual acceptance is claimed**, and the fix was not exercised against a live `0.2.3` profile because that needs an install and a restart. No real marks were written, no temporary server was started, DSH was not restarted, and no other plugin or profile was touched.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.20
```

Publishing does not automatically update your profile. After installation, restart DSH yourself when convenient and refresh the page; colour data needs no migration. **On the `0.2.3` line**, marks cannot be read or saved before this upgrade and recover after it.
