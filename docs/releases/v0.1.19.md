<h3 id="cn-v0.1.19">中文</h3>

| 插件版本 | 最新核查的 DSH | npm 渠道 |
| --- | --- | --- |
| `0.1.19`（本版） | `0.2.2-rc.5` | `latest`（发布后） |
| `0.1.18` | `0.2.2-rc.4` | 已发布 |

### 兼容性与改动

- 新增 DSH `0.2.2-rc.5` 兼容记录，保留此前 16 个已核查版本；同步双语 README、CHANGELOG 与 Release 版本号。
- **本次没有任何可执行代码改动。** 构建标记保持 `host-routes+animated-rows+drag-exclude`，存储格式、Host 半边与加载范围均不变，从 `0.1.18` 升级无需迁移。
- rc.5 的升级指南只有一条：交付组合不再固定搜索提供方，因此使用 DeepSeek 模型路由的会话中，网页搜索改用旧版 Messages 搜索而不是 DeepSeek Search API。该变更改的是 `dsh-web` 的提供方选择逻辑与网页搜索设置页菜单。本插件不注册任何搜索或抓取提供方，也不接触 `ctx.web`，只注入 `webServer` 与 `connection`（两者与 rc.4 逐字节相同），因此该条目不适用。
- 一个值得注意的渠道变化：rc.5 同时成为 npm `latest` 与 `next`，是本插件验证过的首个**同时作为默认安装目标**的候选版本。`alpha` 仍为 `0.2.2-alpha.3`。

### 验证与限制

- 逐包对比 rc.4 与 rc.5 中本插件消费的产物：`dsh-client-ui-layout`、`dsh-client-ui-conversation`、`dsh-client-ui-workspace`、`dsh-client-ui-sidebar`（含会话行结构）、`dsh-base`、`dsh-client-locale`、`dsh-host-webserver`、`dsh-client-connection` 的 `lib` 产物逐字节相同。
- 仅有的两处差异只是内嵌构建标识：`dsh-client-modules/lib/index.js` 与 `dsh-client-ui-sidebar/lib/client.js` 各只改了一个字符串（`rc.4-70005a5` → `rc.5-3f85d88`），不涉及逻辑。外壳自身的 `dist` 产物与 rc.4 逐字节相同，因此 `0.1.17` 依赖的 macOS 拖动 CSS 没有变化，面板仍保留自己的 `data-window-drag-exclude` 声明。`dsh-web` 导出的函数与类集合未变，差别只在其内部的提供方选择逻辑。
- 对已安装的 rc.5 客户端做实时探查：`conversation.session.header.utilities` 中 `session-color-mark` 与 `shell.overlay` 中 `session-color-chips`（order 100）均激活。
- 40 项单元测试全部通过。声明的 `engines.dsh` 与两个 DSH peer 范围通过 `>=0.2.2-alpha.2 <0.3.0` 已接纳 rc.5，且仍拒绝未测过的 `0.2.3-alpha.1` 与 `0.3.0`，本轮未放宽范围。
- **未完成真实 GUI、移动端或跨设备视觉验收**；注册成功不等于视觉验收。没有写入真实标记、没有启动临时服务，也没有重启 DSH。没有修改其他插件，也没有改动本机 profile。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.19
```

发布不会自动更新你的 profile。安装后请在方便时自行重启 DSH 并刷新页面；颜色数据无需迁移。

<h3 id="en-v0.1.19">English</h3>

| Plugin version | Newest assessed DSH | npm channel |
| --- | --- | --- |
| `0.1.19` (this release) | `0.2.2-rc.5` | `latest` (after publishing) |
| `0.1.18` | `0.2.2-rc.4` | published |

### Compatibility and changes

- Add DSH `0.2.2-rc.5` compatibility, retaining the 16 previously assessed versions; synchronise both READMEs, CHANGELOG and Release versions.
- **No executable code changed in this release.** The build marker stays `host-routes+animated-rows+drag-exclude`; storage format, Host half and load range are unchanged. No migration from `0.1.18` is needed.
- rc.5's only upgrade-guide entry removes the fixed search provider from the shipped composition, so web search in a conversation on a DeepSeek model route runs legacy Messages search instead of the DeepSeek Search API. It changes `dsh-web`'s provider selection and the Web search settings menu. This plugin registers no search or fetch provider, never touches `ctx.web`, and injects only `webServer` and `connection` (both byte-identical to rc.4), so the entry does not apply.
- One channel change is worth noting: rc.5 is now both npm `latest` and `next`, making it the first verified release candidate that is also the **default install target**. `alpha` remains `0.2.2-alpha.3`.

### Verification and limits

- Compared every package this plugin consumes across rc.4 and rc.5: `dsh-client-ui-layout`, `dsh-client-ui-conversation`, `dsh-client-ui-workspace`, `dsh-client-ui-sidebar` (including its Session-row markup), `dsh-base`, `dsh-client-locale`, `dsh-host-webserver` and `dsh-client-connection` have byte-identical `lib` artifacts.
- The only two differences are embedded build identities: `dsh-client-modules/lib/index.js` and `dsh-client-ui-sidebar/lib/client.js` each change a single string (`rc.4-70005a5` → `rc.5-3f85d88`), with no logic change. The web shell's own `dist` assets are byte-identical to rc.4, so the macOS window-drag CSS that `0.1.17` depends on is unchanged and the panel keeps its `data-window-drag-exclude` declaration. `dsh-web`'s exported function and class set is unchanged; only its internal provider selection differs.
- Live inspection of the installed rc.5 client: `session-color-mark` active in `conversation.session.header.utilities` and `session-color-chips` active in `shell.overlay` (order 100).
- All 40 unit tests pass. The declared `engines.dsh` and both DSH peer ranges already admit rc.5 through `>=0.2.2-alpha.2 <0.3.0`, and still reject an untested `0.2.3-alpha.1` or `0.3.0`; no widening was needed.
- **No real GUI, mobile or cross-device visual acceptance is claimed**: a registration is not visual verification. No real marks were written, no temporary server was started, and DSH was not restarted. No other plugin was touched and the local profile was not changed.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.19
```

Publishing does not automatically update your profile. After installation, restart DSH yourself when convenient and refresh the page; colour data needs no migration.
