### 兼容性与改动

- 新增 DSH `0.2.2-rc.3` 兼容记录，保留此前 14 个已核查版本；同步双语 README、CHANGELOG 与 Release 版本号。
- 唯一可执行改动：选择器面板在自己的可见边界上声明 `data-window-drag-exclude`。DSH `0.2.2-rc.1` 把 macOS Desktop 的自动 `no-drag` 排除从“任意匹配的控件与 ARIA 角色”收窄为 `data-window-drag` 行内的交互元素，因此覆盖拖动行的自定义浮层必须自己声明窗口区域。本插件的选择器是挂在会话页头（`header[data-window-drag]`）里的固定面板，其饱和度、色相、透明度三个拖拽面是 `role="presentation"` 的普通 div，不在 DSH 的控件清单内。
- 影响谁：在 macOS Desktop 上、窗口高度不足以把面板完全放在页头下方时，把光标放在面板的取色面上拖动此前可能移动整个窗口而不是改变颜色。纯 Web、Windows 与移动端布局不受影响——该排除规则只在 `html[data-platform=darwin]` 下生效。
- 构建标记变为 `host-routes+animated-rows+drag-exclude`：DOM 里仍显示旧标记的设备跑的是缓存客户端，需要强制刷新。
- 存储格式、Host 半边、`engines.dsh` 与 peer 范围均不变（`>=0.2.2-alpha.2 <0.3.0` 已接纳 rc.3），从 `0.1.16` 升级无需迁移。
- 2026-11-14 npm 渠道：DSH `next` → `0.2.2-rc.3`，`latest` → `0.2.2-rc.1`，`alpha` → `0.2.2-alpha.3`。

### 验证与限制

- 逐个对比本插件消费的包在 `0.2.2-rc.1` 与 `0.2.2-rc.3` 之间的产物：`dsh-host-webserver`（exact 路由 `register`）、`dsh-client-connection` 的 Host 半边（`requestRejection`）、locale 的 `register`/`bind`、模块加载器的手写 bundle 契约与 `dsh.client` 字段、`conversation.session.header.utilities` 与 `shell.overlay` 两个槽位声明、`dsh-client-ui-workspace` 的会话行身份（`data-row-key="session:<id>"`、`role="treeitem"`、`aria-selected`）均未改变。会话列表的滚动容器移到 `.listArea` 外层，但它仍是行的祖先，色块裁剪与滚动跟随继续有效。
- 对已安装的 rc.3 客户端做实时探查：`conversation.session.header.utilities` 中 `session-color-mark` 激活（order 40），`shell.overlay` 中 `session-color-chips` 激活（order 100）。
- 40 项单元测试全部通过，其中包含新增的窗口区域测试。**未完成真实的 macOS Desktop 拖动验收，也未完成真实 GUI、移动端或跨设备视觉验收**；注册成功不等于视觉验收。没有写入真实标记、没有启动临时服务，也没有重启 DSH。
- 现有的搜索结果身份回退、写盘失败静默退化等边界不在本次修改范围内。没有修改其他插件，也没有改动本机 profile。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.17
```

发布不会自动更新你的 profile。安装后请在方便时自行重启 DSH 并刷新页面；颜色数据无需迁移。若是 macOS Desktop，重启后确认面板里的取色面可以正常拖动取色、页面其他留白仍可拖动窗口。

### Compatibility and changes

- Add DSH `0.2.2-rc.3` compatibility, retaining the 14 previously assessed versions; synchronise both READMEs, CHANGELOG and Release versions.
- The only executable change: the picker panel now declares `data-window-drag-exclude` on its own visible box. DSH `0.2.2-rc.1` narrowed macOS Desktop's automatic `no-drag` exclusion from "any matching control or ARIA role" to interactive elements inside a `data-window-drag` row, so a custom overlay that can cover a drag row must declare its own window region. This plugin's picker is a fixed panel mounted inside the conversation header (`header[data-window-drag]`), and its saturation, hue and alpha drag surfaces are plain `role="presentation"` divs outside DSH's control list.
- Who is affected: on macOS Desktop, in a window too short to place the panel entirely below the header, dragging on those colour surfaces could move the window instead of picking a colour. Plain Web, Windows and mobile layouts are unaffected — the exclusion applies only under `html[data-platform=darwin]`.
- The build marker becomes `host-routes+animated-rows+drag-exclude`: a device whose DOM still shows an older marker runs a cached client and must be hard-refreshed.
- Storage format, Host half, `engines.dsh` and both peer ranges are unchanged (`>=0.2.2-alpha.2 <0.3.0` already admits rc.3). No migration from `0.1.16` is needed.
- Registry channels on 2026-11-14: DSH `next` → `0.2.2-rc.3`, `latest` → `0.2.2-rc.1`, `alpha` → `0.2.2-alpha.3`.

### Verification and limits

- Compared every package this plugin consumes across `0.2.2-rc.1` and `0.2.2-rc.3`: `dsh-host-webserver` (exact-route `register`), the `dsh-client-connection` Host half (`requestRejection`), locale `register`/`bind`, the module loader's hand-authored bundle contract and `dsh.client` fields, the `conversation.session.header.utilities` and `shell.overlay` slot declarations, and Session-row identity in `dsh-client-ui-workspace` (`data-row-key="session:<id>"`, `role="treeitem"`, `aria-selected`) are unchanged. The session list's scroll owner moved to the `.listArea` wrapper, which is still an ancestor of the rows, so chip clipping and scroll tracking keep working.
- Live inspection of the installed rc.3 client: `session-color-mark` active in `conversation.session.header.utilities` (order 40) and `session-color-chips` active in `shell.overlay` (order 100).
- All 40 unit tests pass, including the new window-region test. **No real macOS Desktop drag acceptance and no real GUI, mobile or cross-device visual acceptance is claimed**: a registration is not visual verification. No real marks were written, no temporary server was started, and DSH was not restarted.
- Existing search-result identity fallback and silent disk-write fallback limits are outside this patch. No other plugin was touched and the local profile was not changed.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.17
```

Publishing does not automatically update your profile. After installation, restart DSH yourself when convenient and refresh the page; colour data needs no migration. On macOS Desktop, confirm after the restart that the panel's colour surfaces drag normally and that the rest of the header still moves the window.
