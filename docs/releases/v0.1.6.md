<h3 id="cn-v0.1.6">📦 兼容性</h3>

| 插件版本 | 已验证的 DeepSeek Harness | npm 发布状态 |
| --- | --- | --- |
| **`0.1.6`** | **`0.2.0-rc.1`（最新 RC）**、`0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2` | 本次发布（`latest`） |

### 为什么发这个版本

旧范围 `>=0.1.7-alpha.2 <0.2.0` 只是靠预发布排序才接纳 `0.2.0-rc.1`；`0.2.0` **正式版**一发布，启动预检会**直接禁用插件行**。

### ⚠️ 变更

- peer 与 `dsh.engines.dsh` 范围改为 `>=0.1.7-alpha.2 <0.2.0-0 || 0.2.0-rc.1 || >=0.2.0 <0.3.0`：已验证的 `0.1.7` 线、精确钉死的 `0.2.0-rc.1`（没人测过的 `rc.2` 进不来）、到 `<0.3.0` 为止的 `0.2.0` 正式版线。
- `dshReleases` 记录 `0.2.0-rc.1`；两份 README 同步。

### ✅ 核对与实测

- 逐包比对两个 tag：加载器与 slot API 只差版本号，peer 预检逐字节相同，行 DOM、`header.utilities`、`shell.overlay` 不变。
- 运行中的 `0.2.0-rc.1` 实例实测：客户端诊断正常、marks 路由 200、头部控件渲染、插件行未被禁用。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.6
```

`dataDir` 保持原样，升级后**重启 `dsh web`**。

<h3 id="en-v0.1.6">📦 Compatibility</h3>

Adapts to DeepSeek Harness `0.2.0-rc.1`: the same code measured working, with the declared range rewritten so the plugin survives the `0.2.0` final release. Zero code change; no migration needed.

| Plugin version | Verified DeepSeek Harness | npm status |
| --- | --- | --- |
| **`0.1.6`** | **`0.2.0-rc.1` (latest RC)**, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2` | this release (`latest`) |
| `0.1.5` | `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2` | published |
| `0.1.2` | `0.1.6-alpha.2` | published (use this on older DSH) |

### Why this release exists

The old range `>=0.1.7-alpha.2 <0.2.0` admitted `0.2.0-rc.1` only through prerelease ordering; on the `0.2.0` **final** release the boot precheck would have **disabled the plugin row**.

### ⚠️ Changes

- The peer and `dsh.engines.dsh` ranges become `>=0.1.7-alpha.2 <0.2.0-0 || 0.2.0-rc.1 || >=0.2.0 <0.3.0`: the verified `0.1.7` line, `0.2.0-rc.1` pinned exactly (an untested `rc.2` stays out), and the stable `0.2.0` line up to `<0.3.0`.
- `dshReleases` records `0.2.0-rc.1`; both READMEs updated.

### ✅ Verified

- Tag-by-tag source comparison: the loader and slot API differ only in version numbers, the peer precheck is byte-identical, and the row DOM, `header.utilities` and `shell.overlay` are unchanged.
- Measured on the running `0.2.0-rc.1` instance: the client diagnostic prints, the marks route answers 200, the header control renders, and the plugin row is not disabled.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.6
```

Keep the `dataDir` configuration, then **restart `dsh web`**.
