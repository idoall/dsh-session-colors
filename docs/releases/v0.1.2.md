### 修了什么

**折叠或展开工作区后，色块会停在原来的位置最长 20 秒。**

- **现象**：把带标记会话的工作区折叠起来，色块还留在原处、盖在下一行上，约 20 秒后才消失；展开时同样要等约 20 秒才出现。
- **根因**：不是轮询间隔本身的问题，而是**折叠/展开根本没有触发重算**——20 秒只是那一次对等轮询顺带重渲染了浮层。真正的根因是 DOM 规范的一条细节：对**同一个 target** 第二次调用 `observer.observe(target, options)` 是**替换** options，而不是合并。浮层为了监听手机抽屉在 `body` 上的 class 变化，在同一个 observer 上又 observe 了一次 `document.body`，于是 `childList` 监听被悄悄顶掉，工作区折叠（行被移除）再也不触发重算。
- **修法**：每个 options 组合各用一个独立 observer（行增删 / `body` class / `aria-expanded` 与 `hidden`），卸载时逐个断开。第三个观察是给"只隐藏不移除"的折叠方式留的后路。

### 谁受影响

- 用颜色标记过会话、并且会折叠/展开工作区的人。折叠或展开后色块现在**立刻**跟着变（实测 1 秒内）。
- 已安装的用户：升级即可，**标记数据不受影响**，不需要做任何迁移。

### 兼容性与升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.2
```

然后在 profile 的 `cordis.patch.yml` 里给一个数据目录，再**重启 `dsh web`**：

```yaml
- id: dsh-session-colors
  config:
    dataDir: /absolute/path/to/profiles/web/data/dsh-session-colors
```

不配 `dataDir` 也能用，但标记只活在宿主进程的生命周期里。宿主半边只在 DSH 启动时加载；客户端半边刷新页面即生效。

### 限制

- **色块依赖 DSH 的行 DOM**：靠 ARIA role 找行、靠 React fiber 取会话 id。DSH 大改侧栏结构后色块可能不再显示；但**不会影响点击**，因为浮层从不接收指针事件。
- **标记属于单个 DSH 实例**：两个独立的 DSH 服务之间不共享。
- **没有权限模型**：能访问该 profile 已鉴权路由的人都能读写标记。
- **只有颜色**：没有文字标签、图标或 emoji。

### What was fixed

**After collapsing or expanding a workspace, a chip stayed at its old position for
up to 20 seconds.**

- **Symptom**: collapsing the workspace that holds a marked Session left the chip
  where it was, on top of the next row, and it only disappeared about 20 seconds
  later. Expanding behaved the same way in reverse.
- **Root cause**: not the poll interval itself — collapsing and expanding simply
  triggered **no re-measure at all**; the 20-second peer poll merely happened to
  re-render the layer. The real cause is a DOM detail: calling
  `observer.observe(target, options)` a second time on the **same target**
  **replaces** the options instead of merging them. To follow the phone adapter's
  `body` class the layer had added a second `observe()` for `document.body` on the
  same observer, which silently dropped the `childList` watch — so a workspace
  collapse, which really does remove rows from the DOM, stopped triggering a
  re-measure.
- **Fix**: each option set now has its own observer (row add/remove, `body` class,
  and `aria-expanded`/`hidden`), all disconnected on teardown. The third one covers
  a collapse that hides rows instead of removing them.

### Who is affected

- Anyone who has marked a Session and collapses or expands workspaces. The chips now
  follow immediately (measured within one second).
- Existing installs: upgrade; **marks are untouched** and no migration is needed.

### Compatibility and upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.2
```

Then give it a data directory in the profile's `cordis.patch.yml` and **restart
`dsh web`**:

```yaml
- id: dsh-session-colors
  config:
    dataDir: /absolute/path/to/profiles/web/data/dsh-session-colors
```

It works without `dataDir`, but then marks live only for the life of the Host
process. The Host half loads only at DSH boot; the browser half reloads on a page
refresh.

### Limitations

- **Chips depend on DSH's row DOM**: rows are found by ARIA role and the Session id
  comes from React internals. A large change to the sidebar structure can stop chips
  from appearing; it **cannot break clicking**, because the layer never accepts
  pointer events.
- **Marks are per DSH instance**: two independent DSH servers do not share them.
- **No permission model**: anyone who can reach the Host's authenticated routes for
  this profile can read and write marks.
- **Colour only**: no labels, icons, or emoji.
