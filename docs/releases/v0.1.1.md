<h3 id="cn-v0.1.1">插件 0.1.1 — 已验证 DeepSeek Harness 0.1.6-alpha.2</h3>

### 版本对应

| 插件版本 | 已验证的 DeepSeek Harness | npm 发布状态 |
| --- | --- | --- |
| **`0.1.1`** | `0.1.6-alpha.2` | 本次发布（`latest`） |
| `0.1.0` | `0.1.6-alpha.2` | 已发布 |

### 改了什么

**只有打包进 npm 的文档变了，代码一行没动。**

- `0.1.0` 的 tarball 是在 README 修正之前打出来的，所以 npm 包页面一直写着"尚未发布"、徽章也是灰的。`0.1.1` 换成了发布后的 README：真实版本徽章、真实的安装命令。
- 新增 `screenshots.json`，声明插件市场详情页展示的三张截图。它放在本仓库里，所以以后换图只要推自己的仓库，不用再给市场列表提 PR。

另外，`0.1.1` 是第一个**完全由标签驱动**的版本：推 `v0.1.1` 标签后，GitHub Actions 通过 npm Trusted Publishing（OIDC）发布，不需要 npm token，也不需要任何人工二次验证。`0.1.0` 是首次发布，必须用凭据引导一次。

### 谁受影响

- **第一次在 npm 上看到这个插件的人**：之前会读到"尚未发布"这句已经不成立的话。
- **已安装的用户**：无需任何操作。行为与 `0.1.0` 完全一致。

### 兼容性与升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.1
```

然后在 profile 的 `cordis.patch.yml` 里给一个数据目录，再**重启 `dsh web`**：

```yaml
- id: dsh-session-colors
  config:
    dataDir: /absolute/path/to/profiles/web/data/dsh-session-colors
```

不配 `dataDir` 也能用，但标记只活在宿主进程的生命周期里。宿主半边只在 DSH 启动时加载；客户端半边刷新页面即生效。

### 限制

- **色块依赖 DSH 的行 DOM**：靠 ARIA role 找行、靠 React fiber 取会话 id。DSH 大改侧栏结构后色块可能不再显示；但**不会影响点击**，因为浮层从不接收指针事件。
- **标记属于单个 DSH 实例**：两个独立的 DSH 服务之间不共享。
- **没有权限模型**：能访问该 profile 已鉴权路由的人都能读写标记。
- **只有颜色**：没有文字标签、图标或 emoji。

<h3 id="en-v0.1.1">Plugin 0.1.1 — verified against DeepSeek Harness 0.1.6-alpha.2</h3>

### Version matrix

| Plugin version | Verified DeepSeek Harness | npm status |
| --- | --- | --- |
| **`0.1.1`** | `0.1.6-alpha.2` | this release (`latest`) |
| `0.1.0` | `0.1.6-alpha.2` | published |

### What changed

**Only the documentation inside the npm package changed; not a line of code.**

- The `0.1.0` tarball was packed before the README fix, so the npm page kept saying
  "not published" behind a grey badge. `0.1.1` ships the post-release README: the
  real version badge and the real install command.
- Adds `screenshots.json`, declaring the three screenshots the plugin-market detail
  view shows. It lives in this repository, so replacing a screenshot later is a
  push here rather than a pull request to the list.

`0.1.1` is also the first **tag-driven** release: pushing the `v0.1.1` tag makes
GitHub Actions publish through npm Trusted Publishing (OIDC) — no npm token and no
manual second factor. `0.1.0` was the first publish, which had to be bootstrapped
once with credentials.

### Who is affected

- **Anyone seeing this plugin on npm for the first time**: the page used to claim it
  was not published.
- **Existing installs**: nothing to do. Behaviour is identical to `0.1.0`.

### Compatibility and upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.1
```

Then give it a data directory in the profile's `cordis.patch.yml` and **restart
`dsh web`**:

```yaml
- id: dsh-session-colors
  config:
    dataDir: /absolute/path/to/profiles/web/data/dsh-session-colors
```

It works without `dataDir`, but then marks live only for the life of the Host
process. The Host half loads only at DSH boot; the browser half reloads on a page
refresh.

### Limitations

- **Chips depend on DSH's row DOM**: rows are found by ARIA role and the Session id
  comes from React internals. A large change to the sidebar structure can stop chips
  from appearing; it **cannot break clicking**, because the layer never accepts
  pointer events.
- **Marks are per DSH instance**: two independent DSH servers do not share them.
- **No permission model**: anyone who can reach the Host's authenticated routes for
  this profile can read and write marks.
- **Colour only**: no labels, icons, or emoji.
