| 插件版本 | 最新核查的 DSH | npm 渠道 |
| --- | --- | --- |
| `0.1.18`（本版） | `0.2.2-rc.4` | `latest`（发布后） |
| `0.1.17` | `0.2.2-rc.3` | 已发布 |

### 兼容性与改动

- 新增 DSH `0.2.2-rc.4` 兼容记录，保留此前 15 个已核查版本；同步双语 README、CHANGELOG 与 Release 版本号。
- **本次没有任何可执行代码改动。** 构建标记保持 `host-routes+animated-rows+drag-exclude`，存储格式、Host 半边与加载范围均不变，从 `0.1.17` 升级无需迁移。
- rc.4 的升级指南只有一条：DeepSeek 流式内容拒答的错误码从 `MALFORMED_RESPONSE` 改为 `CONTENT_REFUSED`。它影响的是对 LLM 错误结束或 `turn/end` 错误做分类的代码；本插件不处理 LLM 错误，两个错误码在源码与测试里都没有引用，因此该条目不适用。
- 2026-11-18 npm 渠道：DSH `next` → `0.2.2-rc.4`，`latest` → `0.2.2-rc.1`，`alpha` → `0.2.2-alpha.3`。

### 验证与限制

- 逐包对比 rc.3 与 rc.4 中本插件消费的产物：`dsh-client-ui-layout`、`dsh-client-ui-conversation`、`dsh-client-ui-workspace`、`dsh-client-ui-sidebar`、`dsh-host-webserver`、`dsh-client-connection`、`dsh-base`、`dsh-web` 的 `lib` 产物逐字节相同。
- 仅有的两处差异只是内嵌构建标识：`dsh-client-modules/lib/index.js` 与 `dsh-client-ui-sidebar/lib/client.js` 各只改了一个字符串（`rc.3-6b729fe` → `rc.4-70005a5`），不涉及任何逻辑。外壳自身的 `dist` 产物（含 `0.1.17` 依赖的 macOS 拖动 CSS 规则）与 rc.3 逐字节相同。
- 对已安装的 rc.4 客户端做实时探查：`conversation.session.header.utilities` 中 `session-color-mark` 激活（order 40），`shell.overlay` 中 `session-color-chips` 激活（order 100）。
- 40 项单元测试全部通过。声明的 `engines.dsh` 与两个 DSH peer 范围通过 `>=0.2.2-alpha.2 <0.3.0` 已接纳 rc.4，本轮未放宽范围。
- **未完成真实 GUI、移动端或跨设备视觉验收**；注册成功不等于视觉验收。没有写入真实标记、没有启动临时服务，也没有重启 DSH。没有修改其他插件，也没有改动本机 profile。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.18
```

发布不会自动更新你的 profile。安装后请在方便时自行重启 DSH 并刷新页面；颜色数据无需迁移。

| Plugin version | Newest assessed DSH | npm channel |

| `0.1.18` (this release) | `0.2.2-rc.4` | `latest` (after publishing) |

### Compatibility and changes

- Add DSH `0.2.2-rc.4` compatibility, retaining the 15 previously assessed versions; synchronise both READMEs, CHANGELOG and Release versions.
- **No executable code changed in this release.** The build marker stays `host-routes+animated-rows+drag-exclude`; storage format, Host half and load range are unchanged. No migration from `0.1.17` is needed.
- rc.4's only upgrade-guide entry moves the DeepSeek streamed content refusal code from `MALFORMED_RESPONSE` to `CONTENT_REFUSED`. It applies to code that classifies LLM error finishes or `turn/end` errors; this plugin handles no LLM errors, references neither code in source or tests, and is therefore unaffected.
- Registry channels on 2026-11-18: DSH `next` → `0.2.2-rc.4`, `latest` → `0.2.2-rc.1`, `alpha` → `0.2.2-alpha.3`.

### Verification and limits

- Compared every package this plugin consumes across rc.3 and rc.4: `dsh-client-ui-layout`, `dsh-client-ui-conversation`, `dsh-client-ui-workspace`, `dsh-client-ui-sidebar`, `dsh-host-webserver`, `dsh-client-connection`, `dsh-base` and `dsh-web` have byte-identical `lib` artifacts.
- The only two differences are embedded build identities: `dsh-client-modules/lib/index.js` and `dsh-client-ui-sidebar/lib/client.js` each change a single string (`rc.3-6b729fe` → `rc.4-70005a5`), with no logic change. The web shell's own `dist` assets — including the macOS window-drag CSS that `0.1.17` depends on — are byte-identical to rc.3.
- Live inspection of the installed rc.4 client: `session-color-mark` active in `conversation.session.header.utilities` (order 40) and `session-color-chips` active in `shell.overlay` (order 100).
- All 40 unit tests pass. The declared `engines.dsh` and both DSH peer ranges already admit rc.4 through `>=0.2.2-alpha.2 <0.3.0`; no widening was needed.
- **No real GUI, mobile or cross-device visual acceptance is claimed**: a registration is not visual verification. No real marks were written, no temporary server was started, and DSH was not restarted. No other plugin was touched and the local profile was not changed.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.18
```

Publishing does not automatically update your profile. After installation, restart DSH yourself when convenient and refresh the page; colour data needs no migration.
