<h3 id="cn-v0.1.0">插件 0.1.0 — 已验证 DeepSeek Harness 0.1.6-alpha.2</h3>

### 版本对应

| 插件版本 | 已验证的 DeepSeek Harness | npm 发布状态 |
| --- | --- | --- |
| **`0.1.0`** | `0.1.6-alpha.2` | 本次首发 |

`peerDependencies` 声明的加载范围是 `>=0.1.6-0 <0.2.0`（`dsh-client-ui-layout`、`dsh-client-ui-conversation`）。范围不等于已验证：只有上面这一行是实际跑过的版本。

### 这个版本是什么

给任意会话上一个颜色，在侧栏一眼认出它：

- **会话行上的颜色标记**——行左侧内边距里的一条 `4×16` 竖条，**刻意避开状态点**，所以"哪个跑完了"这个信号不会被盖掉。
- **系统风格选择器**——注册在会话头部的工具簇（不占标题位）：大色板、色相与透明度滑条、十六进制与 RGBA 输入、七个主题色、我的颜色，以及浏览器支持时的屏幕吸色。
- **标记存在宿主上**，不在浏览器里：电脑上选的颜色，手机上也能看到，局域网地址与隧道访问都算。DSH 自带的用户设置服务只对回环页面做宿主持久化（`persistence = $host.isLoopback ? "host" : "memory"`），所以本插件走自己的路由 `GET`/`POST /plugins/dsh-session-colors/marks`，落盘到 profile 数据目录里的 `session-colors.json`。
- **手机端同样显示**：手机把侧栏变成抽屉时，色块跟着抽屉移动，并且画在抽屉之上。

### 问题修复

首发之前修掉的两个问题：

- **手机上色块看不见。** 两个原因叠加：① DSH 把 `shell.overlay` 限制在自己的层叠上下文里（`z-index: 20`），而手机适配层把侧栏提升成 `position: fixed; z-index: 10000` 的抽屉，抽屉的不透明背景把色块整片盖住；② 抽屉是 `transform` 滑进来的，没有滚动、没有 resize、没有 DOM 变更，浮层因此一直停在抽屉关上时的屏外坐标。现在浮层通过 portal 渲染到 `document.body`，按行祖先链**实测**该画在哪一层（桌面 1，这类抽屉后面 10001），并跟随祖先的 CSS 过渡。
- **选择器的十六进制字段少一位。** 输入框只有 51px，而 `#FFCC00` 需要 58px，面板里显示成 `#FFCC0`。加宽 hex 列并收紧输入框内边距后，实测 `61/61`。

### 兼容性与升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.0
```

然后在 profile 的 `cordis.patch.yml` 里给一个数据目录，再**重启 `dsh web`**：

```yaml
- id: dsh-session-colors
  config:
    dataDir: /absolute/path/to/profiles/web/data/dsh-session-colors
```

不配 `dataDir` 也能用，但标记只活在宿主进程的生命周期里。宿主半边只在 DSH 启动时加载；客户端半边刷新页面即生效。

### 限制

- **色块依赖 DSH 的行 DOM**：靠 ARIA role 找行、靠 React fiber 取会话 id。DSH 大改侧栏结构后色块可能不再显示；但**不会影响点击**，因为浮层从不接收指针事件。
- **标记属于单个 DSH 实例**：两个独立的 DSH 服务之间不共享。
- **没有权限模型**：能访问该 profile 已鉴权路由的人都能读写标记。
- **只有颜色**：没有文字标签、图标或 emoji。

<h3 id="en-v0.1.0">Plugin 0.1.0 — verified against DeepSeek Harness 0.1.6-alpha.2</h3>

### Version matrix

| Plugin version | Verified DeepSeek Harness | npm status |
| --- | --- | --- |
| **`0.1.0`** | `0.1.6-alpha.2` | first release |

`peerDependencies` declares the loadable range `>=0.1.6-0 <0.2.0` for
`dsh-client-ui-layout` and `dsh-client-ui-conversation`. A range is not a
verification: only the row above was actually run.

### What this release is

Give any Session a colour and spot it at a glance in the sidebar:

- **A colour mark on the Session row** — a `4×16` bar in the row's left padding
  that **deliberately avoids the status dot**, so "which one finished" is never
  covered up.
- **A system-style picker** in the Session header's utilities (not next to the
  title): a large saturation/value field, hue and alpha sliders, hex and RGBA
  fields, seven theme swatches, saved colours, and screen eyedropper where the
  browser supports it.
- **Marks live on the Host**, not in the browser: a colour chosen on your computer
  is also there on your phone, over a LAN address or a tunnel alike. DSH's own
  user-settings service host-backs settings only for loopback pages
  (`persistence = $host.isLoopback ? "host" : "memory"`), so this plugin owns its
  route `GET`/`POST /plugins/dsh-session-colors/marks` and persists to
  `session-colors.json` in the profile's data directory.
- **Visible on a phone too**: when a phone turns the sidebar into a drawer, the
  chips travel with it and are painted above it.

### Fixes

Two problems were fixed before the first release:

- **Chips were invisible on a phone.** Two causes stacked: (1) DSH confines
  `shell.overlay` to a stacking context of its own (`z-index: 20`), while the
  mobile adapter promotes the sidebar to a `position: fixed; z-index: 10000`
  drawer whose opaque background painted over every chip; (2) that drawer slides in
  with a `transform`, firing no scroll, resize or DOM mutation, so the layer kept
  the off-screen coordinates it had while the drawer was closed. The layer now
  renders through a portal on `document.body`, measures the row's own ancestor
  chain to paint one level above whatever holds the sidebar (1 on a stock desktop,
  10001 behind such a drawer), and follows an ancestor's transition.
- **The picker's hex field dropped a character.** The input was 51px wide for a
  58px value, so the panel showed `#FFCC0`. The hex column is wider and the inputs
  carry tighter padding now; measured `61/61`.

### Compatibility and upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@0.1.0
```

Then give it a data directory in the profile's `cordis.patch.yml` and **restart
`dsh web`**:

```yaml
- id: dsh-session-colors
  config:
    dataDir: /absolute/path/to/profiles/web/data/dsh-session-colors
```

It works without `dataDir`, but then marks live only for the life of the Host
process. The Host half loads only at DSH boot; the browser half reloads on a page
refresh.

### Limitations

- **Chips depend on DSH's row DOM**: rows are found by ARIA role and the Session id
  comes from React internals. A large change to the sidebar structure can stop
  chips from appearing; it **cannot break clicking**, because the layer never
  accepts pointer events.
- **Marks are per DSH instance**: two independent DSH servers do not share them.
- **No permission model**: anyone who can reach the Host's authenticated routes for
  this profile can read and write marks.
- **Colour only**: no labels, icons, or emoji.
