DSH `0.2.1-alpha.3` 不需要功能改动；本版只把它列为已验证兼容，并把 `0.2.1` 元组写进声明的加载范围。

兼容最新 DSH `0.2.1-alpha.3`；已验证清单仍保留 `0.2.0-rc.2`、`0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1` 与 `0.1.7-alpha.2`。`0.1.7` 及更早版本已发布（`0.1.7` 在 alpha.3 上同样能正常加载），本版发布后 npm `latest` 指向 `0.1.8`。

<h3 id="cn-v0.1.8">⚠️ 调整</h3>

- **没有功能代码改动。** DSH 的启动预检在上一版声明的范围下就已接纳 alpha.3，插件行不会被跳过。
- **范围新增一个分支。** peer 与 `dsh.engines.dsh` 增加 `>=0.2.1-alpha.3 <0.3.0`，让"已验证"与"允许加载"在两种判定规则下都说得通；运行时行为不变。
- **升级后可见变化只有一处。** `0.2.1-alpha.3` 从此明确列为已验证兼容；色块依赖 DSH 行结构的既有边界不变。

### 升级

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@latest
```

---

DSH `0.2.1-alpha.3` needs no functional code change; this release only marks it verified and names the `0.2.1` tuple in the declared load range.

Verified against the current DSH `0.2.1-alpha.3`; the list also keeps `0.2.0-rc.2`, `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1` and `0.1.7-alpha.2`. `0.1.7` and earlier are published (and `0.1.7` already loads on alpha.3); after this release npm `latest` points at `0.1.8`.

<h3 id="en-v0.1.8">⚠️ Changed</h3>

- **No functional code changed.** DSH's boot precheck already accepted alpha.3 under the previous declared range, so the plugin row was never skipped.
- **The range gains one alternative.** The peers and `dsh.engines.dsh` add `>=0.2.1-alpha.3 <0.3.0`, so "verified" and "allowed to load" both hold under either evaluation rule; runtime behaviour is unchanged.
- **There is one visible upgrade effect.** `0.2.1-alpha.3` is now explicitly listed as verified; the existing limit that chips depend on DSH's row DOM is unchanged.

### Upgrade

```sh
dsh plugin --profile web add @idoall/dsh-session-colors@latest
```
